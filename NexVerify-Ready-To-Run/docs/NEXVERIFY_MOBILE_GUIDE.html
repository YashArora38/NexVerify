5. ProofGrid Scoring Engine (Math & Rules)

Formula: Score = max(0, 100 - Total Penalties)

Penalty RangeVerdictMeaning
≥ 70 PointsHIGH_RISKClear fraud signs (Score constrained ≤ 10/100).
55 - 69 PointsSUSPICIOUSMultiple high-risk warning flags.
31 - 54 PointsCAUTIONBe careful; context must be verified.
≤ 30 PointsVERIFIED_OFFICIALOfficial domain (.gov.in / .bank.in) or verified brand.
≤ 30 PointsLOW_RISKVerified company + old domain + regulatory listing.
≤ 30 PointsUNKNOWNNothing proves who runs it (Score capped at 50, UI shows '?').
Ethical Security Principle: NexVerify me absence of evidence is NOT proof of safety. Agar koi unknown site par koi scam report nahi hai, par koi identity proof bhi nahi hai, toh use "SAFE" nahi bolte, balki UNKNOWN mark karte hain!

6. Payment Intel & Fake Gateway Detection

A. Strict Gateway Whitelist:

Code: backend/app/payment_intel.py: gateway_for()

Scheme must be https, port 443, zero credentials, aur exact host match:

  • Razorpay: checkout.razorpay.com, api.razorpay.com, rzp.io
  • Cashfree: sdk.cashfree.com, payments.cashfree.com
  • PhonePe Merchant: mercury.phonepe.com, merchants.phonepe.com

Agar koi hacker razorpay.scamsite.com banaye ya HTML me "Razorpay Verified" likhe, toh use verified gateway nahi maanta.

B. Sensitive Form Analysis:

Agar input me password, otp, pin, cvv, aadhaar, card_number ho:

  • Form submits over unencrypted HTTP → -60 Points (`INSECURE_SENSITIVE_FORM`)
  • Form submits to unverified 3rd party domain → -35 Points (`SENSITIVE_EXTERNAL_FORM`)
  • Form uses GET method (exposing data in URL) → -35 Points (`SENSITIVE_QUERY_STRING`)

7. Blockchain Architecture & Smart Contract

Solidity Contract: CommitmentAnchor.sol (Solidity ^0.8.20)

Function: anchor(bytes32 commitment) external onlyWriter
Selector: 0x54be8d59 (First 4 bytes of Keccak-256 hash of "anchor(bytes32)")

Off-Chain vs On-Chain (Judges Ko Yeh Samjhana):

Raw evidence, user queries aur URLs kabhi blockchain par nahi jaate (Privacy violation aur gas cost bachaane ke liye).
Evidence files ka SHA-256 hash → Merkle Root → 32-byte cryptographic salt jodkar ek final 32-byte Salted Commitment banta hai.
Backend me blockchain.py is commitment ko unsigned EVM calldata me format karta hai: 0x54be8d59<32_byte_commitment>.
User apne Web3 wallet (MetaMask) se is transaction ko sign karke Sepolia testnet par deploy kar sakta hai.
